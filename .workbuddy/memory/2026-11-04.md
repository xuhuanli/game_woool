## 美术优化第一批：接触阴影 + 统一烘焙布光

诊断结论（全部实据核对过）：模型本身不是瓶颈，让画面显廉价的是渲染层三件事。
1. 全场没有投影 —— 90 张精灵表烘焙时透明底只做描边，GameScene 里也没有 shadow 对象，角色浮在地砖上。
2. 角色/道具两套光照：角色 Hemi(2.2)+sun(-3,5,4,3.2)+蓝轮廓光 0.8，道具 Hemi(2.0)+sun(-3,6,4,3) 无轮廓光。
3. buildings.ts `roof()` 瓦垄方向写歪：`band = onFront ? i : j` 配合上一行 `-(halfW - slope)/1 < ...`（halfW 除了 1、halfD 没除），四坡出来是斜向同心条纹。
另：53 个角色条目只有 32 个模型（Mage ×7、Rogue_Hooded ×5）；preload 一次拉 58.3MB / 90 张表。

已做（第一批）：
- 新增 `src/render/shadows.ts`：128×64 径向渐变椭圆，`SHADOW_SPREAD=0.44`、`SHADOW_DEPTH_GAP=0.5`。
- `GameScene`：UnitView 加 shadow 字段，addUnitView/addNpc 建阴影，syncUnit 每帧同步位置/深度/透明度（死亡淡出、重生淡入自动跟随 sprite.alpha），removeUnitView 销毁。
- 景观阴影不改精灵、而是烘进地表贴图：`groundPainter.paintGround(scene, map, shadowWidth?)` 新增第三参数，`paintDecorShadows` 用同一张 stamp 逐件 drawImage（2500 件约一次填充成本，运行时零开销）。
- 新增 `tools/bake/lighting.ts`（`addStudioLighting`，默认值=角色那套），kaykit.ts / props.ts 改为共用；下次重烘景观才会看到变化。

验证：tsc 通过、203 个测试全绿。无头 Chrome 在本机 sandbox 里起不来（sandbox init / GPU process exit 6），截图验证改由人工开 localhost:5199 看。

待办（后续批次）：建筑屋顶重做（四坡分面、瓦垄沿坡向）、檐下 AO；角色模块化换装提升差异化；按地图懒加载 + pngquant（58MB → 约 15MB）。

## 美术优化第二批：屋顶重做 + 檐下阴影（已重烘 56 张景观图）

- 重写 `tools/bake/buildings.ts` 的 `roof()`：原来是一张 40×40 网格按 i/j 奇偶上色，`band = onFront ? i : j` 配合写歪的比较式，四坡出来是斜向同心条纹。现在拆成四个独立坡面（前后梯形、左右三角形），u 沿檐线、v 沿坡长，瓦垄按 `TILE_PITCH=0.3` 等距切条，每根拆成左右两半起脊（`TILE_HEIGHT=0.05`），正脊附近用中间色过渡压掉高频噪点。
- 檐口加瓦当（`EAVE_LIP=0.09`，沿檐线 24 段），屋顶不再是纸片。
- 新增 `eaveShade()`：墙顶压一层自上而下淡出的暗色渐变（4 个面，共用一张 4×64 贴图），hall/house/tower 都调用。
- hall 的匾额从 2.4 缩到 1.9 并前移到 `coreD*0.31+0.09`，不再被下层屋顶吞掉。
- 重烘全部 56 个景观（props.json + PNG）。烘法是 `npx vite --config tools/bake/vite.config.ts` 起 5180，再用无头 Chrome + CDP 打开 props.html 等 `#status` 变成"完成"。
